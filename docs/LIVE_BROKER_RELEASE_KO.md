# 실거래 브로커 출시 체크리스트

이 문서는 ATS 매칭 코어가 아니라, 사용자가 자신의 증권계좌로 실제 주문을 전송하는 별도 브로커 라우팅 서비스의 출시 절차입니다.

## 현재 구현

- 사용자별 토스증권·한국투자증권·키움증권 연결
- AES-256-GCM 자격증명 암호화와 마스킹
- 토큰 캐시, 실시간 잔고·시세, 매수·매도 사전검사
- 사용자별 주문수량·금액·일일금액·미체결 한도
- PostgreSQL 분산 잠금, 고정 출발 IP 잠금, 사용자 동의, version CAS 킬 스위치
- 60초 일회성 미리보기와 최종 확인문구
- 중복 방지 주문 원장, 주문·취소, 불확실 상태, 체결대사, 감사로그

## 토스증권에서 준비할 것

1. [토스증권 Open API](https://home.tossinvest.com/ko/open-api)에서 신청합니다.
2. 토스증권 WTS의 `설정 → Open API`에서 Client ID와 Client Secret을 발급합니다.
3. 운영 서버의 고정 outbound IPv4를 허용 IP로 등록합니다. 서버리스의 변동 IP로는 실거래를 열지 않습니다.
4. UI의 `계좌 추가 → 토스증권`에서 각 사용자가 자신의 키를 직접 등록합니다. 계좌번호와 `accountSeq`는 계좌조회 API로 자동 선택할 수 있습니다.
5. 토스증권 계좌에서 국내주식 통합주문(SOR) 사용 설정을 완료합니다.

## 한국투자증권에서 준비할 것

1. [KIS Developers](https://apiportal.koreainvestment.com/)에서 Open API 서비스를 신청합니다.
2. 실전 또는 모의 App Key·App Secret을 발급하고 계좌번호 8자리와 상품코드 2자리를 확인합니다.
3. UI의 `계좌 추가 → 한국투자`에서 키와 계좌정보를 직접 등록합니다.

## 키움증권에서 준비할 것

1. [키움 REST API](https://openapi.kiwoom.com/)에서 서비스를 신청하고 App Key·Secret Key를 발급합니다.
2. UI의 `계좌 추가 → 키움증권`에서 실전 또는 모의를 선택하고 키를 등록합니다. 계좌번호는 공식 `ka00001`로 자동 확인합니다.
3. 연결 검증은 토큰, 주문가능금액(`kt00001`), 계좌평가잔고(`kt00018`) 조회가 모두 성공해야 완료됩니다.
4. 모의투자는 키움 공식 제약에 따라 KRX만 사용합니다. 실전 KRX/NXT/SOR 주문은 주문 미리보기와 전역 게이트를 통과해야 전송됩니다.

## 배포 잠금 해제 순서

1. 운영 환경에 32자 이상의 무작위 `CREDENTIAL_ENCRYPTION_KEY`를 secret으로 저장합니다.
2. 고정 출발 IP를 마련하고 증권사에 등록한 뒤 연결·잔고·시세·주문조회만 먼저 검증합니다.
3. 최소금액·1주·지정가·정규장 시나리오로 주문/취소/부분체결/완전체결/거부/타임아웃 대사를 검증합니다.
4. D1이 아닌 PostgreSQL `DATABASE_URL`에서 동시 주문 한도·원장 검증을 통과합니다.
5. 승인된 운영자만 `TRADING_ENVIRONMENT=production`, `LIVE_MARKET_ENABLED=true`, `LIVE_TRADING_EGRESS_READY=true`, `LIVE_TRADING_ENABLED=true`, `LIVE_ORDER_ROUTING_RELEASED=true`를 설정합니다.
6. 각 사용자는 별도로 위험동의와 한도를 설정해야 하며, 모든 주문은 최종 확인을 거칩니다.

신규 주문 release gate를 다시 내려도 기존 미체결 주문의 취소와 대사는 계속 가능해야 합니다. 미체결·불확실 주문이 남아 있는 계좌 연결은 자격증명을 삭제할 수 없습니다.

## 운영 전 필수 보완

- 고정 egress 프록시 또는 전용 실행 워커와 장애 이중화
- 요청 속도 제한, 주문 우선순위 큐, 브로커별 circuit breaker
- 토큰 발급 단일화(재발급 시 기존 토큰 무효화 방지)
- 실시간 체결 이벤트 또는 짧은 주기 대사 워커
- 암호화 키 KMS/HSM 이전과 키 회전
- 관리자 RBAC, 이상주문 탐지, 비상 전체취소, 사고 대응 runbook
- 이용약관·개인정보·전자금융/투자중개 관련 법률 및 증권사 제휴 검토

실제 ATS는 개인별 증권사 API를 받지 않습니다. 증권사 회원의 OMS가 전용망·회원 프로토콜로 ATS에 주문을 보내며, 청산·결제·시장감시까지 별도 기관 인터페이스가 필요합니다.
