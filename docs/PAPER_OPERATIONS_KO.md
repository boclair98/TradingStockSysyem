# 가상매매 운영과 API 준비

2026-10-28 기준. 운영 주소는 https://tradingstocksysyem.coders.kr/ 이다.

## 지금 사용할 흐름

1. 로그인 → 내 자동화 → 전략 설계에서 가격 조건·수량·예산을 저장한다.
2. 위쪽 가상 운용에서 저장한 전략을 선택하고 `가상 운용 시작`을 누른다.
3. `연습 기록 만들기` 또는 직접 확보한 가격 기록을 입력한다. 형식은 `시간대 포함 ISO 시각,가격,체결가능수량`이다. 헤더 없이 한 번에 1~50줄.
4. `가격 기록 재생`을 누르면 서버가 순서대로 조건을 평가해 가상 주문·부분체결·예약금·보유종목·수수료를 반영한다.
5. 가상 원장·최근 처리 이력·CSV를 확인한다. `운용 중지`는 미체결을 취소하고 잔고와 이력을 남긴다.

처음에는 가상 현금 1억원, 보유주식 0주다. 가상 계좌는 공동 매칭 LAB 계좌 및 실제 증권계좌와 별도로 저장한다. 사용자 간에는 데이터가 공유되지 않는다. 매수·매도 각 0.015%를 가정하며, 최소 정수 단위로 올림한다. 실제 증권사 수수료·세금·시장 충격·호가 대기열을 재현하지 않는다. 일일 한도는 KST 기준의 현재 운용 세션 한도다. 새 운용은 별도 세션이며 과거 세션의 한도를 합산하지 않는다.

시작할 때 전략 설정을 복사하므로 전략 보관함을 수정해도 진행 중인 세션에는 영향을 주지 않는다. 미체결이 있으면 신규 주문을 추가하지 않는다. 시장가는 입력된 유동성만 체결하고 잔량을 취소한다. 지정가는 가격 조건에 맞을 때 틱별 수량 한도 안에서 체결한다. 재생 명령 중 입력 오류가 하나라도 있으면 전체를 반영하지 않는다.

현재는 USER_REPLAY 입력 기록만 처리한다. 실시간 시세 API, 브라우저 종료 후 지속 수신, 자동 스케줄러는 아직 연결하지 않았다. 가상 체결이 실제 거래소에서 같은 가격으로 체결된다는 뜻은 아니다.

## 데이터와 저장 공간

- 운영 PostgreSQL: Coders `db` 서비스, 현재 manifest 기준 1Gi. `DATABASE_URL`은 플랫폼이 주입한다.
- `paper_simulation_accounts`: 사용자별 잔고·포지션·세션·최근 주문 snapshot, version CAS.
- `paper_simulation_commands`: 사용자별 명령 키·요청 해시·처리 이벤트. 계좌 변경과 같은 트랜잭션에 저장한다. 재전송은 이벤트를 재실행하지 않고 현재 원장을 반환한다.
- 화면/CSV는 최근 종료 주문 100건과 모든 미체결을 보여준다. 명령 이벤트는 삭제하지 않는다. 화면 조회는 최근 20개 명령으로 제한한다.
- 다중 인스턴스에서도 DB CAS와 PK를 사용한다. 프로세스 메모리를 개인 원장의 기준으로 쓰지 않는다.
- 다수 사용자를 받기 전 DB 제공자의 백업·복원 방법, 보관기간, 1Gi 증설과 모니터링을 정해야 한다. 앱 코드만으로 백업이 확보됐다고 주장하지 않는다.

## 필요한 API / 가져올 정보

### 1. 가격 기록 재생 운영

증권사 API, 실계좌 번호, HTS ID는 필요하지 않다. 사용 권한이 있는 시각·가격·수량 기록만 준비하면 된다. 이 단계에는 새 플러그인이 필요하지 않다.

### 2. 다른 사용자도 보는 국내 실시간 가상매매

아래 공식 경로에서 **웹/앱 공개 표출과 가상매매용 처리를 허용하는 시장데이터**를 문의한다.

- KRX 공식 수신방법: https://openapi.krx.co.kr/contents/OPP/DATA/OPPDATA003.jsp
- 코스콤 데이터 서비스: https://data.koscom.co.kr/
- 문의 경로: https://www.koscom.co.kr/portal/bbs/B0000033/list.do?menuNo=200654

문의 문구 예시: “국내 주식 가상매매 웹 서비스에서 다수 회원에게 시세를 표시하고 자동 조건을 평가하려 합니다. 실시간 또는 지연 시세, 최우선 호가/체결가/체결량, 재배포·저장·모의체결 이용 범위, 과금과 기술 수신 규격을 안내해 주세요.”

가져올 것은 ① 제공사와 계약/승인 범위 ② REST/WebSocket/전문 규격서 링크 ③ 마스킹한 응답 예시 ④ 종목코드·타임스탬프·sequence·가격·수량 필드 ⑤ 호출/접속 제한과 재접속 규칙 ⑥ 키 발급 및 IP 등록 절차다. 이 정보로 feed 어댑터·중복제거·지연검사·재수신·내구성 실행기를 결정한다. 토큰만 받아 임의 규격으로 연결하지 않는다.

### 3. 본인 한국투자증권 계좌의 별도 모의투자

- 서비스 신청 안내: https://apiportal.koreainvestment.com/about-howto
- 서비스 범위/시세 제약: https://apiportal.koreainvestment.com/about-open-api

본인 계좌 API를 시험하려면 모의투자용 APP Key, APP Secret, 모의계좌 번호와 상품코드가 필요하다. 토스 계좌 번호를 한국투자증권 계좌 번호 대신 넣지 않는다. 이 경로는 개인 시험용이며 서비스 공용 시세 배포 권한을 주지 않는다. 한국투자증권 공식 안내는 개인 고객의 시세 제3자 제공을 금지하고 제휴법인의 화면 표출에도 별도 정보이용계약을 요구한다.

## 비밀값 저장

키·비밀번호·계좌번호는 채팅이나 GitHub에 붙이지 않는다. 기존 `.env.local`은 Git에서 제외돼 있고 이름만 확인했으며 값을 출력하거나 새로운 제공사 요청을 보내지 않았다. 개인 시험용 설정과 공용 서비스 시세 자격증명은 분리한다.

운영 키는 공급자와 규격이 정해진 뒤 Coders 프로젝트의 **서버 Secret 환경변수**에 넣는다. URL·브라우저 JS·README에는 넣지 않는다. 키가 필요할 때는 실제 어댑터가 읽는 변수 이름을 확정하고 빈 양식을 제공한다. 아직 읽지 않는 가상의 변수나 임의 endpoint를 만들어 설정을 요구하지 않는다.

## 출시 전 남은 운영 항목

- 라이선스 feed + 내구성 시세 수신/전략 실행기와 장애·중복·재시작 시험
- PostgreSQL 실환경 부하 및 동시성 검증, 백업 복원 훈련, 용량/오류 알림
- 이용약관·개인정보 보관/삭제 절차와 지원 연락처
- 실제 증권사 주문 출시 시에는 별도 계약, 사용자별 연결, 승인과 대사가 필요하며 현재 모든 실주문 release gate는 잠겨 있다.

이 버전은 입력 기록을 사용하는 가상매매 베타다. 지속 실시간 운용이나 실거래 서비스 완료로 표시하지 않는다.
