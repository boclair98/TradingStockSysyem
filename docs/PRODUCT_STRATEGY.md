# Trading Stock System 제품 전략

## 한 문장 전략

수익을 약속하는 서비스가 아니라, 사용자가 자동주문 규칙을 **안전하게 만들고 검증하고 운영할 수 있게 하는 도구**를 만든다.

결제는 출발점이 아니다. 사용자가 반복해서 돌아오는 가치 루프와 운영 신뢰가 먼저이며, 수익화는 그 기반 위의 상시 운영 편의와 기업 기능에 연결한다.

## 해결하려는 문제

자동매매를 시작하려는 사용자는 보통 다음 세 가지 위험을 동시에 겪는다.

1. 내가 만든 조건이 경계값에서 정확히 동작하는지 알기 어렵다.
2. 전략 설계, 시세, 주문, 계좌 위험한도가 한 화면에서 연결되지 않는다.
3. 외부 API 오류나 중복 실행이 실제 금전 손실로 이어질 수 있다.

따라서 첫 제품은 “많이 거래하게 하는 화면”보다 “실행하기 전에 틀린 조건을 발견하는 흐름”을 제공해야 한다.

## 핵심 가치 루프

```mermaid
flowchart LR
    A[가격 조건 전략 설계] --> B[수량·일일 예산 검증]
    B --> C[조건 충족 시나리오 점검]
    C --> D[조건 대기 시나리오 점검]
    D --> E[결정 이력과 준비도 확인]
    E --> A
    E -. 격리 Paper Broker 이후 .-> F[모의 실행]
    F -. 운영 승인 이후 .-> G[상시 실거래 자동화]
```

현재 구현은 `A~F`이며 F는 사용자 입력 가격 기록을 쓰는 격리 가상 운용이다. 가상 현금·보유종목·부분체결·수수료·원장과 CSV를 제공한다. 실제 주문 경로와 지속 실시간 실행기는 연결하지 않는다. [운용 안내](PAPER_OPERATIONS_KO.md)에 체결 가정과 API 준비를 정리했다.

## 핵심 사용자

| 사용자 | 현재 제공 가치 | 다음 제공 가치 |
|---|---|---|
| 자동매매 입문자 | 전략 초안, 경계값 점검, 예산 이해 | 개인 Paper 포트폴리오, 알림 |
| 숙련 투자자·개발자 | 결정 이력, 설정 해시, idempotency | 복합 조건, 브로커별 실행 정책 |
| 소규모 운용팀 | 안전 게이트와 감사 가능성 확인 | 승인 흐름, 조직 권한, 장기 감사 보관 |
| 금융기관 기술 검토자 | 매칭·게이트웨이·운영 경계 평가 | 전용망, SLA, 규제·대사 인터페이스 |

## 제품 원칙

- 안전 기능, 킬 스위치, 주문 취소, 기본 감사 이력은 유료로 잠그지 않는다.
- 수익률, 체결 가능성, 실시간 시세를 생성하거나 보장하지 않는다.
- 증권사 연결 전에도 전략 설계와 시나리오 검증은 가능해야 한다.
- 전략 설정이 바뀌면 이전 검증 완료 표시는 무효화한다.
- 실전 주문과 Paper 검증은 UI·API·저장 경계에서 분리한다.
- 웹 프로세스의 타이머를 상시 실행기로 사용하지 않는다.
- 실거래 자동화는 durable queue, 실행 lease, outbox, 대사와 별도 동의가 준비된 뒤에만 연다.

## 수익화 가설

수익화 대상은 투자 수익이나 안전장치가 아니라 **안정적인 자동화 운영 비용을 대신해주는 가치**다.

| 구분 | 무료 핵심 | 향후 유료 후보 |
|---|---|---|
| 개인 | 전략 초안, 수동 시나리오 점검, 기본 이력, 안전장치 | 상시 실행 워커, 복합 조건, 장기 분석, 다중 계좌, 고급 알림 |
| 팀 | 개인 기능과 기본 내보내기 | 조직 권한, 승인 흐름, 장기 감사, 팀 대시보드 |
| 기관 | 기술 평가 자료 | 전용 배포, 전용망, SLA, 운영 지원, 적합성·대사 연동 |

가격을 정하기 전에 다음 지표를 먼저 측정한다.

- 첫 전략 저장 완료율
- 첫 세션에서 조건 충족·대기 두 시나리오를 모두 확인한 비율
- 7일 내 다시 전략을 수정하거나 점검한 사용자 비율
- 위험검사로 사전에 발견된 설정 오류 수
- 모의 실행 단계에서 주문 중복 없이 완료된 비율
- 사용자가 직접 개입해야 했던 오류의 빈도와 복구 시간

## 수익화 진입 기준

다음 조건 전에는 결제 기능을 제품 중심에 배치하지 않는다.

1. 전략 설계부터 검증 완료까지의 핵심 퍼널을 실제 사용자 데이터로 측정할 수 있다.
2. 격리 Paper Broker와 durable runner가 재시작·중복·장애 상황 테스트를 통과한다.
3. 오류·지연·대사 상태를 사용자와 운영자가 모두 확인할 수 있다.
4. 안전 기능이 요금제와 무관하게 항상 제공된다.
5. 유료 후보 기능에 대해 반복 사용 의사와 지불 의사를 별도로 검증했다.

## 하지 않는 것

- 수익 보장, 종목 추천, 가짜 실시간 시세
- 공동 매칭 랩을 개인 수익률 시뮬레이터로 재사용
- 브라우저 또는 웹 서버 `setInterval` 기반 상시 주문
- 사용자 동의 없는 증권사 주문
- 안전 기능의 유료화
- 운영 승인을 받지 않은 기능을 “실거래 가능”으로 표시
